# Native Metricool media and external schedule observations

The native import path does not upload or schedule media. An existing authorized upload operator can deposit an owner-only JSON receipt at `reports/clippers-daily-learning/native-media-imports/<assetId>.json`. A reviewed prepare packet explicitly selects `mediaProvider: "metricool"`; packets without this selector retain the existing Drive behavior. No new credentials, OAuth connection or publishing flags are introduced.

The receipt must have `schemaVersion: 1`, `provider: "metricool"`, `kind: "metricool_native_media_receipt"`, `status: "ready"`, the exact `assetId` and destination, `renderReceiptSha256`, `renderRequestSha256`, `sha256`, `sizeBytes`, `mediaUrl`, `resource`, `verifiedAt`, `verification: "anonymous_exact_bytes_sha256"`, `authorizedManifestSha256` (SHA256 of JSON.stringify of the complete prepare packet), `paidSpendAllowed: false` and `paidSpendUsd: 0`. `resource` identifies an actual returned S3 bucket/key or `{kind: "metricool_cdn_url", url}` for an observed native UI upload. No Drive file ID is fabricated. Only the actually observed queryless `https://static.metricool.com/video/<owner>/<YYYYMM>/<name>.mp4` URL shape is admitted. Preparation checks request/packet/render/source/target rights as before, then anonymously streams and hashes the exact native bytes before writing provider-specific evidence and queue input. A failed import never falls back to a new upload. The initial receipt is immutable; live byte verification is repeated rather than changing the receipt digest to refresh its age. Rights freshness and expiry remain independent and unchanged.

`reconcileExternalMetricoolSchedule` is a read-only provider observer for clips the owner already scheduled in Metricool. Its external input is `{destination, metricoolId, scheduledAt, caption, mediaUrl, sha256, sizeBytes}` bound to an existing private prepare packet, request and immutable render receipt. It validates local bytes and anonymously verifies public bytes, then uses the existing adapter's exact scheduler GET. A past scheduled time is accepted as historical observation; this grants no publishing eligibility. The observer records `origin: "external_owner_ui"` in a separate `external-schedules.json` ledger. It never inserts learner deliveries, supplies an artificial pipeline ACK, awards career points, claims a publication timestamp or supplies performance metrics.

The external observation is durable before any reusable native media receipt is written, under the shared scheduler lock. Both daily and weekly dispatch paths consult it, including exact asset/media identity and the verified original-source interval. New IDs, crops, reencodes or URL aliases cannot replay the same source interval. Missing interval proof retains the conservative source URL guard. Corrupt or contradictory dispatch ledgers hold rather than becoming an empty list. Report projection leaves unobserved accounts unknown and partial external observations without complete daily coverage have an unknown shortfall.

The observer CLI accepts only `--observe <private-external.json> --asset <id>` and the existing `CLIPPERS_WORKSPACE_ROOT` / `CLIPPERS_CONFIG_ROOT` metadata pointers. It performs no provider writes. It must not be run as a shortcut for publishing or before independent review and installation.

Calendar accounting reserves known `PUBLISHING` rows. A `PUBLISHED`/`POSTED` row with an exact owned public post URL can also reserve capacity while analytics lags; its original calendar hour is occupied, but no publication timestamp or metric completeness is invented. Once the exact platform ID appears in analytics it is counted once, using the measured publication time. Unknown statuses, wrong owners, conflicting identities, incomplete pagination and opaque provider attribution remain held.

Validation uses synthetic local FFmpeg media and fake transports. This change does not prove any real upload, booking or publication; those require separate actual provider GET and public-byte receipts. Rollback restores the prior scripts together; keep private external observation files as audit/no-replay evidence and do not resume dispatch with code that ignores them.
