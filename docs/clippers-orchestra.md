# Clippers orchestra: reports, accounts and company careers

The owner surface is `GET /api/clippers/orchestra/status`, mounted behind the existing authenticated single-owner Clippers guard and repeating that same identity check. It accepts no selectors, has no POST controller, returns private/no-store, and sanitizes unavailable data as HTTP 503. A missing or malformed snapshot must render as disconnected, not as a static healthy fixture. `shared/clippers-orchestra.ts` is the version-1 strict parser/type contract consumed by the independently developed office area.

The nine roles are deterministic adapters around real pipeline work: supervisor, analytics, trends, streamers, editor, checker, publisher, learning and health. They are not nine continuously running paid models. Execution timestamps, receipt identifiers, evidence IDs, counts and held reasons are projected from actual private files. No running state is invented; without an actual active execution lease `activeUntil` is null. Only the transport health role receives the server-observed authenticated device heartbeat. A watchdog report's time is a last execution observation, not nine separate heartbeats. Expected next pipeline cycle comes from the actual watchdog's configured New York hour; it does not establish that a job has run.

## Separate analytics scopes

The 10:00 watchdog can run the new read-only whole-account collector before its existing preparation/learning stages. It reads the last seven days for all four approved destinations, verifies the provider profile and exact public post URL, retains observation time and actual post age, and records private receipts under `reports/clippers-account-analytics/latest.json`. A same-day report is cached for six hours. A whole collection is bounded to 90 seconds; provider bodies are capped at 2 MiB and at most 200 posts per destination are projected. The read-only fetch facade permits profile/analytics GETs and only the existing `getBrandSettings` metadata MCP operation, never scheduling or another brand/network. Missing credentials, ambiguous provider rows, timeouts and identity conflicts are held. No new key or paid model is used.

Whole-account `totalViews` is a sum of the returned posts' cumulative counters, not views earned in the past 24 hours. Actual ages are age-at-provider-observation when supplied, otherwise age-at-retrieval; a retrieval timestamp does not establish a provider measurement period. Posts without trustworthy public identity/metrics are counted as rejected/partial in the private collector receipt. Whole-account observations never enter controlled rendering experiments or publication receipts.

The existing approved-queue observations remain separately bucketed at 24, 72 and 168 hours, preserving actual age and provider observation timestamps. Unknown engagement counts are null, not invented zeros. Learning requires same destination, creator/language/context, current baseline/candidate version, one changed variable, exact age window, at least five distinct public posts per arm, current render/request/manifest/scoped-media receipt bindings, at least 20% views lift, and no completion/cost/time regression. Three independent experiments with no reused posts, matching manifests, and at least two quality improvements are required before the view says manual queue review is available. It never promotes automatically. Recorded policy activations are not proof of subsequent performance improvement.

## Mac → Office transport and persistence

`script/clippers-orchestra-report.mjs` is a read-only private-file projector. Files must be regular owner-only files, without symlinked parents, with size and row limits. It never renders, uploads, posts, fetches media, contacts WhatsApp or calls a model. `script/clippers-orchestra-relay.mjs` asynchronously caches one bounded envelope per minute and owns no credential and no request function. The existing authenticated device helper appends an optional `clippersOrchestra` field to its unchanged heartbeat URL/body, retries only an unacknowledged nonce, and stops including it after an accepted reply. There is no new public endpoint or browser-auth bypass. Telemetry is allowed only to the two owner-verified connected Office HTTPS origins (`robertwebsites.com` and `robplanner.replit.app`, same Replit project), with no credentials/query/fragment in the URL; an unverified origin skips the extension and preserves legacy behavior. Telemetry-bearing requests reject redirects.

The existing server heartbeat bearer check runs before this optional field is processed. Malformed Clippers telemetry returns a safe field-level rejection without interrupting the original BlackRoom heartbeat. Optional persistence has a 1.5-second response budget and at most one in-flight request per process: a slow acknowledgement stays unconfirmed and is reconciled by the same nonce rather than delaying or multiplying the original heartbeat work. The receiver checks schema, exact scope, 256 KiB limit, UUID nonce, non-future timestamps, generation order and duplicate payload digest. A duplicate takes a read-only fast path; a transaction checks races. It stores only the sanitized projection in a namespaced owner key in the existing `agent_council_state` KV table; no schema/startup DDL is added. Its digest uses stable key-sorted canonical JSON, so PostgreSQL JSONB reordering cannot corrupt it. Immutable stored reports are validated against their original generation time; GET downgrades aged signals and transport freshness without making an old report prevent replacement.

Transport freshness is 90 seconds; source freshness is independently derived from the actual evidence time, not the GET response time. Receiving a current heartbeat does not refresh the age of old source reports. If the relay, original device auth, reports or database are unavailable, the view remains disconnected/stale/held. No connection claim is valid until an actual Mac → Office authenticated ingest and owner GET have been observed after the reviewed installation.

### Creator discovery and scoped adaptation

The priority catalog follows Robert's 11 requested names as 13 verified YouTube channel IDs and 10 canonical creator groups. Jordi Wild/The Wild Project share a group; Rubius and Germán's two channels remain distinct channels in their respective groups. TJR is the confirmed trading creator. Identity research establishes no republication rights. Public discovery keeps metadata only and never downloads or promotes a source into an approved asset.

The discovery budget is 14 official RSS GETs per UTC day: 13 priority channels plus one bounded rotating challenger. Each response is limited to 256 KiB (at most 3.5 MiB/day), two concurrent reads and a 90-second cycle. A durable daily reservation ledger counts uncertain requests, cached requests retain their original observation time, and prior same-day legacy receipts consume the same budget. Initial migration can therefore have fewer than 13 priority reads that day. There are no paid model or API calls, identity searches, retries that bypass the daily cap, or media acquisition.

Creator preference is separate from render-parameter policy promotion. The learner validates each ready asset with its existing rights, media and render gates. An asset can participate only when its existing private, hash-reviewed evidence also includes `creatorSelection`: exact `channelId`, `sourceVideoId`, optional reviewed `sourceEpisodeId`, `format`, `context`, `postingBand` (`HH:00`), `timezone: America/New_York`, and `windowHours` (24, 72 or 168). The hour band is declared before assignment and derived from the approved render manifest's slots; it never adds slots or changes scheduled times. Missing context remains unmeasured. It does not request another ranking approval or create a publication permission.

Under the existing learner writer lock, the adapter saves three prospective cohort manifests and each individual assignment before calling the provider. Each cohort has five control and five challenger slots and an expiry declared at registration (at most 30 days). A sample requires the same destination, language, format, context, render manifest/engine, hour band and observation window, actual age inside its nominal 24-hour bucket and all ten members of each sealed cohort in the same observed one-hour age bin, current publication receipt, distinct original video/file/episode, direct completion rate, zero cost and measured elapsed time. Missing, invalid or unknown assigned members remain in the cohort as unmeasured; they are not filtered out to manufacture five samples. Historical deliveries without these assignments never become retrospective experiments.

Automatic preference requires all three cohorts to achieve at least 20% median view improvement without completion, time or cost regression. The adapter persists the original baseline, verified incumbent, evidence digest, decision, transition and expiry. A new challenger must beat the current verified incumbent; beating an obsolete baseline cannot displace it. Current readiness and the original winning evidence are revalidated to preserve a preference; expired evidence falls back to the safe baseline. Preferences live at most 24 hours and only order already-ready assets inside their exact scope. A pending trial receives one already-ready challenger position within that scope, preserving exploration without increasing the five-post daily cap, changing another format's positions, or authorizing publication. Expired unsuccessful trials rotate to the least recently attempted available creator.

Private routing state and reports live under `reports/clippers-creator-selection/`. The Office receives only bounded aggregate decisions, reasons, sample counts and expiry; no captions, source files or private evidence are exported. Creator decisions do not earn heartbeat points, establish new training qualifications or claim performance improvement without measured evidence.
### Metricool analytics request contract

The official [Metricool Swagger](https://app.metricool.com/api/swagger.json), linked by the [API integration guide](https://help.metricool.com/basic-guide-for-api-integration-r97af), specifies local second-precision `from`/`to` dates and an optional timezone for the analytics endpoints. The adapter preserves UTC boundaries by sending `YYYY-MM-DDTHH:mm:ss` and `timezone=UTC`. The earlier fractional UTC suffix form returned HTTP400 in the authorized read-only diagnostic; the corrected form returned HTTP200 for the approved TikTok and Facebook diagnostic targets. Authentication remained inside the existing helper.

Only a JSON array or recognized `data` array is accepted. The official Facebook endpoint description mentions CSV; a CSV response therefore remains held until a separately verified normalizer exists. The observed connection returned JSON. A missing/invalid format, unknown list shape or HTTP error produces a bounded held code, never a fabricated zero. No completion/retention metric is inferred or changed by this fix.

Collector receipts now bind `adapterContract=utc-local-v1`; an older receipt from the rejected request format is not reused as the corrected contract. The first corrected receipt retains the ordinary six-hour cache, including truthful held outcomes.
